## 2024-07-01 - Insecure CORS and Authentication Logic in Edge Functions
**Vulnerability:** Edge Functions used `Access-Control-Allow-Origin: "*"` which allows any domain to make cross-origin requests to the endpoints. Additionally, the edge functions incorrectly used `supabase.auth.getClaims(token)` which does not exist in supabase-js v2.
**Learning:** Hardcoding wildcard CORS origins exposes endpoints to CSRF and other cross-origin attacks. Edge functions should dynamically use an environment variable or safe default (e.g., `Deno.env.get("CORS_ORIGIN") || "http://localhost:5173"`). Authentication of JWT tokens in Supabase Edge Functions with `supabase-js` v2 must use `supabase.auth.getUser(token)` instead of deprecated/non-existent `getClaims` methods.
**Prevention:** Avoid wildcard CORS policies (`*`) in production code, always default to restricting origins. Verify SDK documentation for authentication mechanisms to ensure correctly validating tokens, using `supabase.auth.getUser(token)` correctly instead of legacy methods.
